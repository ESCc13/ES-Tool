## ModPc 图形界面嫁接（网易 MC 第三方客户端）

用户给了工作区的 `ModPc.zip`（33MB），是网易我的世界中国版的第三方客户端
（`Login.exe` 602KB，.NET Framework 4.6 / x86，VB+Newtonsoft+McL.Core 混合）。
诉求：嫌纯命令行难用，要一个全功能图形界面。

### 做法（源码级嫁接，不是外壳）

1. `unzip` 到 `modpc/ModPc`，`strings` 拿不到（无 strings.exe，自写 `_tools/ustrings.py` 提 UTF-16LE）
2. `dotnet tool install -g ilspycmd` → 反编译 `Login.exe` 得 **129 个 .cs，一次编译 0 错误**
   - ilspycmd 实际路径：`~/.dotnet/tools/.store/ilspycmd/11.2.0.10050/ilspycmd.win-x64/.../ilspycmd.exe`
   - `~/.dotnet/tools` 下的 `ilspycmd.cmd` 在 Git Bash 里直接调不到，要用上面的 exe 全路径
3. 全局 `sed 's/\bConsole\./Term./g'`，新写 `Term.cs` 实现同名成员
   （Write/WriteLine/ReadLine/ReadKey/Clear/ForegroundColor/Title/Error），语法零改动
4. `Environment.Exit(0)`（登录失败直接退进程，共 3 处）→ `throw new ModPcFatalException(...)`
   （类放**全局命名空间**，否则各命名空间下引用不到）
5. 入口 `text.Program.Main` 改名 `LegacyMain`，新写 `ModPcGUI.Boot.Main` 启 WinForms
6. net46 / x86 / WinForms，输出单个 `ModPcGUI.exe`（352KB），丢进 ModPc 目录即用
   （依赖同目录 mcl.common.dll / Mcl.Core.dll / Newtonsoft.Json.dll / config.json）

### 命令目录自动生成

`_tools/parse_cmds.py` 解析 `app.cs` 的 `Command()` 大括号块，为每条命令提取
`ReadLine` 顺序 + 前置 `Write` 提示 → 再配 `Help()` 里的中文说明，生成
`Commands.g.cs`：**184 条命令 / 11 个分类 / 参数提示全自动**。
另有 36 条 Help 里没有的用 `EXTRA_LABELS` 手补中文。

### 踩过的坑

- **WinForms Dock 顺序**：索引越大越先占位。所以先 Add(Fill)，再 Add(Bottom)，
  再 Add(Top) 且**从视觉最下往上加**。搞反了整块布局会倒过来。
- **.ps1 必须 UTF-8 带 BOM**：无 BOM 且含中文时 PowerShell 5.1 静默失败，
  连第一行都不执行（连输出文件都不生成），排查半天才发现是编码。
- **截 GUI 窗口**：`CopyFromScreen` 只能抓前台；用 `PrintWindow`（flags=0 或 2）。
  最小化窗口 GetWindowRect 返回 160x28，先 `ShowWindow(h, 4)`=SW_SHOWNOACTIVATE
  恢复但不抢焦点，再 PrintWindow。
- 用户当时在玩 Minecraft，强行 SetForegroundWindow 会打断他 → 用 C 方案。
- `bash` 里 `nohup x &` 起的 GUI 进程会随工具调用结束被清掉，
  要用 Bash 工具的 `run_in_background`。

## 13:03 修：一键布吉岛 HttpListener 端口冲突

用户报 `HttpListenerException (0x80004005): 在前缀"http://127.0.0.1:11451/"上侦听失败，
因为它与计算机上的现有注册冲突`，连点几次都失败。

**根因**：他同时开了 **4 个** ModPcGUI 实例（tasklist 实测 4 个 PID）。
`app.Command()` 里 `fastbjd` → `Http.Authserver(11451)` 是硬编码单端口，
原代码 catch 后只 `Term.WriteLine(ex.ToString())`，于是整个堆栈糊在日志里，功能无声失败。
`netstat` 看到 11451 挂在 PID 4（http.sys 统一托管，不代表某个具体进程）。

**三处修复**：
1. `Http.Authserver(port)` 改成 **端口递增重试**（11451→11460），
   成功后写回 `AuthServerUrl`（`FastAUTHgame()` 用的就是它，所以游戏 mc.cfg 会跟着变）；
   全失败才打印人话提示（"把其他 ModPc 窗口关掉"）。顺手给 Result() 循环加了 catch+Sleep(50)。
2. 新增 `Http.CloseAuthserver()`，`MainForm.OnFormClosing` 调用，关窗口立刻释放端口。
3. `Boot.Main` 加 **Mutex 单实例锁**（`ModPcLauncher_SingleInstance_v1`），
   第二个窗口直接弹提示拦下；`--multi` 可强制多开。

附带修了 `LogView.PushSystem`：原来 `» → 一键布吉岛` 会接在 `3101237375>> `

## 15:32 修：换皮肤后游戏崩溃

用户报「选择皮肤启动一启动游戏过一会就崩溃」，且连试了 4 张（skin/ 下 4 个副本，
15:23/15:25/15:26/15:29）。检查文件：全是标准 64×64 8bit RGBA(colortype 6)，
steve.png 也是同格式 —— **尺寸/编码不是原因**。

**真正原因**：我上一轮把 mc.cfg 的皮肤三元组改了：
`skin=<自定义路径>` + `md5=文件真实md5` + 新增 `skin_info.slim`。
原版是 `skin=steve.png` + `md5=e5a2e67d…（固定）` + `iid=-1`、从不设 slim。
客户端很可能拿 md5 当缓存键/走另一条皮肤加载分支，三元组一变就跑一会儿崩。

**修法：配置永远不变，只换文件内容**
- `SkinManager.SkinPath` 永远返回 `BaseDir\steve.png`；`SkinMd5` 永远 `DefaultMd5`；
  `Slim` 永远 false
- `SetSkin()` 不再 `img.Save()` 重新编码（GDI+ 重编码也可能埋雷），改成
  **字节原样 `File.Copy` 覆盖 steve.png**
- 首次更换备份原版为 `steve_original.png`；`ResetToDefault()` 还原
- 删掉 Function.cs(6) + app.cs(3) 里我加的 `skin_info.slim = …` 行，恢复原版
- `SkinDialog` 的细手臂勾选禁用（原客户端只认 Steve 模型）
- `Load()` 检测旧版 skin.json 的 `path` 字段自动迁移；启动时自检 steve.png，坏了还原备份
- `skin.json` 只存 label/source 给 UI 显示，不再参与 mc.cfg

**现场数据迁移**（直接改文件，不用等用户重选）：
- `steve_original.png` ← 原版(2960B)
- `steve.png` ← `skin_20261107_152952.png`(1388B，即桌面的 11.png)，md5 对齐
- `skin.json` 重写成新格式

验证截图：头像变成皮肤像素头、皮肤卡显示「自定义：11.png」，ui.json 记忆的地址
/登录方式都还在。新 exe 15:36 已部署到 modpc 与 dist。

**教训**：动客户端的本地配置时，能保持原值就别改语义；「换成动态正确值」未必比
「保持原版固定值 + 只换实际文件」安全。这个坑和 md5 对不上那次是同一个根。

     设好，否则构造函数会用相对 URI 再加载 PclStyles.xaml 抛 IOException
  4. 分步落盘（main entered → app ok → runtime → styles → pre-ctor →
     ctor → measure → shot）+ 事件日志（Get-WinEvent Application Level=2）
     是定位"进程秒退无输出"的组合拳
- **产出**：offscreen_launch.png / offscreen_feature.png——启动页无日志卡片、
  功能页有，迁移验证闭环。以后 UI 验证默认走离屏渲染，不再弹窗。

### Phase 7：房间查 IP 无输出修复（23:10-23:18）

用户反馈：点「查 IP」根本没效果、没有 IP 端口输出。

- **Bug 1（主因）：跨线程 UI**——DoRoomIp 在 KickOff 后台线程里直接调
  AppendLog（_logBox.AppendText），抛 InvalidOperationException，
  流程在 Process.Start 之前就断了，异常被 KickOff 的 catch 吞成一行
  "线程异常"。修复：新增 LogUi()（Dispatcher.BeginInvoke 包 AppendLog），
  后台线程日志全走它。
- **Bug 2：BOM**——账号文件是 C# Encoding.UTF8 写的（带 EF BB BF），
  Go json.Unmarshal 不认 BOM，lobbyip 解析整个失败 → "缺少 sdkuid/sessionid"。
  修复：写临时 sauth 前 TrimStart('\uFEFF')。
- **顺手**：stdout/stderr 改异步收集（BeginOutputReadLine）防同步
  ReadToEnd 互等死锁；超时 120s 明确提示。
- **端到端验证（live_es9.ps1）**：--demo 启动（离线=已登录态）→ 自动填
  假房间号 123456789 → 点「查 IP」→ 切功能页截图。运行日志显示全链路：
  票据读取（pc 模式 615 字节）→ lobbyip 真实登录网易成功（uid=953753727）
  → 查询 → "无法找到该房间"（假房间号预期错误）透传到日志。
  真实房间号会出 `地址 : ip:port` 并回填地址框。
- **脚本坑**：PS 函数参数内联 cast `ClickAt [int](...) [int](...)` 会把
  "[int]" 当字面参数——必须先赋值变量再传。
